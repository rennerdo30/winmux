## What it is

A terminal multiplexer splits a terminal into panes. WinMux splits a **window** into panes, and a
pane can hold a terminal, an ordinary Windows application, or a file browser. The arrangement — the
splits, the tabs, what each pane was running and which directory it was in — is written to a file
and restored next time.

## What it is not

WinMux restores **processes**, not process state. A restored shell is a new shell in the right
directory, not the one you left with its scrollback and running jobs. Nothing can restore those, and
saying otherwise would be the fastest way to make the feature look broken.

Application compatibility is real but not universal. Some applications refuse to be embedded and are
hosted alongside instead; elevated ones cannot be hosted at all. See
[Troubleshooting](/troubleshooting/).
