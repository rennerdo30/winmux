Nothing in Settings is inert. Every control changes something visible, and what cannot be changed
yet is shown as information rather than as a switch that does nothing.

## Appearance

**Theme** — Follow Windows, Dark or Light. Following Windows switches with the system setting while
WinMux is running.

## Profiles

The list of everything you can open in a pane. See [Profiles](/profiles/).

## Terminal

**Font** — a fallback list, so a machine without the first still gets a monospaced face. The default
is `Cascadia Mono, Consolas, monospace`; Cascadia Mono is not on a stock Windows install, so the
second entry is the common case.

**Font size** — in pixels, 6 to 72.

WinMux **measures** the font you choose and builds its character grid from that measurement, so the
cursor, selection, search highlights and coloured cell backgrounds line up with the glyphs whichever
font is actually in use.

**Notifications** — when a program asks for your attention in a pane you are not looking at, WinMux
shows a Windows notification naming the pane; click it to go straight there. *Messages and bells*
(the default) counts a plain terminal bell too; *Messages only* counts only explicit notifications
(OSC 9, 777 and 99); *Off* turns them off. If Windows notifications are switched off in
Settings › System › Notifications, Windows shows nothing from any app — WinMux says so here and in
the status bar.

**Claude Code notifications** — Claude Code only sends desktop notifications to terminals it
recognises, and WinMux is not one of them. *Set up…* sets `preferredNotifChannel` to `iterm2` in
Claude Code's `settings.json`, after showing you exactly what will change. Every other setting is
kept and the old file is backed up beside it. To do it by hand instead, add
`"preferredNotifChannel": "iterm2"` to `~/.claude/settings.json`. Restart running Claude sessions to
pick it up.

## New panes

**Default terminal** — which profile a new terminal pane opens, and what the prefix key's split
commands use. The list *is* the profile list, so "which terminals do I have" and "which one opens by
default" stop being two unrelated ideas.

**Tabs in a new group** — which edge a stack's strip takes when you first tab a pane.

## Sessions

**Confirm before closing running panes** — asks first when an action would close a pane with a
program still in it.

Below it, the paths: session file, settings file, profiles file. They are selectable, because the
reason to look at a path is almost always to go there.

## Working directories

**Set up…** installs the shell snippets that make directory capture work. Read
[Sessions](/sessions/) before deciding you do not need them.

## Updates

**Check for updates on start**, and **Releases to offer**. See [Updates](/updates/).

## Files

Settings and profiles are TOML in your user profile; the session is TOML wherever you opened it.
All three are meant to be readable, and the panes section of a session file is meant to be edited.
